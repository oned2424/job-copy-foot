# ヒアリングプロトコル

このスキルの前提は「**派遣元の代表が関わらなくても3案ができる**」ことである。
したがってヒアリングは、代表の手を止めない量に抑える。

## 手順の順序（守る）

```
1. ヒアリング履歴を読む → 2. 質問を出す → 3. 回答を待つ → 4. A/B/C の3案を出す
```

**質問と3案を同時に出さない。**回答の内容で3案の中身が変わるため、先に案を出すと作り直しになる。
回答が「不明」ばかりでも、回答が返ってきてから案を作る。

## 原則

1. **往復は1回。**追加の質問を思いついても次の依頼まで持ち越す。
   往復が1回である以上、**1回で聞く問数を絞ることに意味はない**。絞って足りなければ、
   原稿が薄いまま出るか、往復が2回になるかのどちらかにしかならない。
2. **質問数は「目標字数に届くか」で決める。**（v2で変更。旧ルールは「2回目以降は3問まで」）
   - まず、`appeal-formula.md`の`fieldTargets.roles`の各欄について、
     **いま手元の確定事実だけで`targetMin`に届くか**を見積もる。
   - 届かない欄があれば、その欄を`fills`に持つ質問を`question-catalog.json`から引き、
     **届く見込みが立つまで質問に積む**。上限は設けない。
   - 全欄が届く見込みなら、質問は資格の必須／歓迎と年齢構成の2問で終わる。
   - 迷ったら聞く。**聞かなかった質問は永久に埋まらないが、聞いた質問は1回で終わる。**

**なぜ変えたか。**旧ルールで実際に出た原稿は、仕事内容244字（目標400）・求める人材85字（目標150）
だった。競合は同じ欄を383字書いている。原因は文章術ではなく**書ける事実の不足**であり、
その不足は「3問まで」という上限が作っていた。往復1回という制約は守りつつ、
1回で聞く量は原稿が必要とする量に合わせる。

3. **答えが返ってこない項目があっても原稿は完成させる。**未回答は欠陥ではなく想定内の状態として扱う。
4. **未回答の項目は原稿に一切書かない。**推測で埋めない。「たぶん20〜30代が多い」は書かない。
5. **確認していない緩和表現は書かない。**「未経験可」「入社後に資格取得可」「◯t限定でも可」は、
   フロントが明示的にYESと答えた場合だけ使う。応募後に条件が違うと分かるのが最も損害が大きい。
6. 質問は**フロント（派遣元の営業）が即答できる粒度**にする。派遣先へ問い合わせないと分からない
   ことを含めない（それは次回の依頼までに埋める項目）。

## ヒアリング履歴を先に読む

質問を作る前にヒアリング履歴スプレッドシートを読む。
**すでに `確認済み` の項目は質問候補から外す。**同じことを毎回聞かせない。

```bash
python3 scripts/hearing_log.py read --client foot \
    --site 派遣先名 --office 事業所名 --title 職種
```

出力は層1・層2・層3の3ブロックに分かれる。0件なら**初回の事業所**＝質問数を制限しない。
`--title` に依頼フォーマットの■職種をそのまま渡すと、層3がさらに2つに割れる。

| 層 | 対象 | read での扱い | 例 |
|---|---|---|---|
| 層1（FooT全社） | 全案件で不変。派遣元の方針・制度 | **二度と聞かない** | 性別・主婦主夫系タグの方針／社会保険／Web面接可否／応募先連絡先 |
| 層2（事業所・恒久） | 派遣先の事業所に紐づく | **同じ事業所なら聞かない** | 住所・TEL・FAX・抵触日・試用期間・年間休日・交通費・制服・積み降ろし設備・駐車場・ロッカー・喫煙 |
| 層3（案件限り） | 案件ごとに変わりうる | **前回回答を提示して差分だけ確認する** | **年齢構成**・資格の必須／歓迎・作業量／本数・残業・繁閑・きつい所と楽な所・班の人数 |

| 列 | 使い方 |
|---|---|
| 状態 | `確認済み`＝再質問しない／`未回答`＝再質問の候補／`要再確認`＝必ず聞く |

**年齢構成は層3。**同じ事業所でも、ルートや職種が変われば現場の年代は変わる。事業所単位で使い回さない。

### 層の正本は question-catalog.json（E列ではない）

層の判定を毎回AIにやらせない。`references/clients/{client}/question-catalog.json` が
質問文と層を1:1で固定しており、`hearing_log.py` は書き込み時も読み出し時もこれを優先する。

スプレッドシートのE列は**書き込んだAIの申告値**でしかない。実測では8行すべてが層3へ倒れており
（層の判断を都度させると安全側＝層3に寄る）、層1・層2が空のまま「二度と聞かない」が
一度も発動していなかった。`read` が「E列の層が実態と違う行を N 件補正しました」と出したら、
スプレッドシート側のE列も直す。

### 層3は白紙で聞き直さない

前回回答があるなら、`read` が出す差分確認の文をそのまま使う。

```
- 中型自動車免許は必須ですか、歓迎ですか。（前回この事業所では「必須」でした。今回も同じですか）
```

白紙で「中型免許は必須ですか、歓迎ですか」と聞くと、フロントに同じ説明を最初からさせることになる。
差分確認も**1問と数える**。前回回答が無い層3は通常の質問として聞く。

### ただし職種が違う案件の層3は流用しない

層3は**案件限り**の回答である。同じ派遣先・同じ事業所でも、職種が変われば
手積みの有無・必要な資格・服装・立ち仕事かどうかはまるごと変わる。
それを「前回この事業所の回答」として出すと、**別の仕事の事実が新しい原稿に入る。**

`read --title 職種` を渡すと、層3が2ブロックに割れる。

| ブロック | 扱い |
|---|---|
| `■ 層3：すでに回答がある項目` | 上のとおり差分確認にする |
| `■ 層3：別の職種の案件の回答。流用しない` | **前回回答として見せない。**通常の質問として聞き直す |

判定は職種名の近さ（文字2-gram の Dice 係数・しきい値 0.25）で行う。表記ゆれは吸収するが、
`倉庫内フォークリフト作業` と `中型トラックで中子の輸送スタッフ募集` は 0.00 で落ちる。

職種はまず履歴のJ列を見る。J列が空の行だけ、案件番号からJoblistのH列（職種名）で補う。
**J列を優先するのは、新規案件はJoblistに行が無く引けないため。**
どちらでも分からない行は流用させない（判定できないものを「前回の回答」として渡さない）。

質問して回答を得たら、そのつどヒアリング履歴に追記する。
**未回答だった事実も1行として残す**（聞いていないのか、聞いたが答えが無かったのかを後から区別するため）。

```bash
python3 scripts/hearing_log.py append --client foot \
    --site 派遣先名 --office 事業所名 --job 12204054 --title 職種 \
    --rows /tmp/hearing_rows.json
```

`--title` は必須。J列に職種を残さないと、次のセッションで上の「職種が違う案件は流用しない」判定が
できなくなる。新規案件（案件番号が `YYYYMMDD_派遣先名` の仮名）ではJoblistから引けないため、
ここで残すのが唯一の経路になる。

`--rows` の形式。`layer` と `state` は下の値以外を書くとスクリプトが止まる（勝手に丸めない）。

```json
[{"layer": "層3（案件限り）", "question": "中型免許は必須ですか、歓迎ですか",
  "answer": "必須", "state": "確認済み"},
 {"layer": "層3（案件限り）", "question": "現場の年齢構成はどうなっていますか",
  "answer": "わからない", "state": "未回答"}]
```

| フィールド | 取りうる値 |
|---|---|
| `layer` | `層1（FooT全社）` / `層2（事業所・恒久）` / `層3（案件限り）` |
| `state` | `確認済み` / `未回答` / `要再確認` |

`layer` は question-catalog.json に載っている質問なら**書いた値より カタログが優先される**
（`append` 時に「層をカタログで補正: …」と表示される）。カタログに無い質問だけ、書いた値が使われる。

## 質問の選び方

依頼を受けたら、まず**依頼フォーマットの7項目**（派遣先／事業所／職種／任せる仕事／勤務時間・シフト／
時給／採用予定人数）と、層1・層2のマスタで埋まる項目と、ヒアリング履歴で`確認済み`の項目を除外する。
残った不明点から、**原稿の訴求が変わる項目**を優先して選ぶ。

**案件番号をフロントに聞かない。**派遣先＋事業所＋職種でJoblistを引いて特定するのはスキル側の仕事である。
複数ヒットしたときだけ、候補を並べて選んでもらう（これは質問数に数えない）。

| 優先度 | 種類 | 例 |
|---|---|---|
| 高 | 応募資格の必須／歓迎の別 | その免許・資格は必須か、歓迎か |
| 高 | 勤務地の特定（事業所が複数ある場合） | どの事業所か |
| 高 | **現場の年齢構成** | **いま働いている方はどの年代が多いか** |
| 高 | **仕事内容(No.7)が400字に届かない場合の穴埋め** | **1日の流れ・扱う荷物・作業の内訳・使う機械・教育期間・班の人数** |
| 中 | 事実欄が`targetMin`に届かない場合の穴埋め | 空調／装備／設備／定着年数／実際の月収／繁閑 |
| 低 | 表現の好み | 硬め／柔らかめ |

### 欄から質問を引く（`fills`）

`question-catalog.json`の各質問は`fills`に「その答えが入る欄（role）」を持つ。
**埋まっていない欄 → その欄を`fills`に持つ質問**、という順で引く。逆順（質問ありきで選ぶ）にしない。

| 欄 | 引ける質問id |
|---|---|
| `description`（No.7 仕事内容） | `daily_flow` / `cargo_type` / `work_ratio` / `forklift_type` / `equipment_used` / `daily_volume` / `training_period` / `team_size` / `site_scale` / `loading_equipment` / `hard_easy` / `busy_season` |
| `personal`（No.28 求める人材） | `license_required` / `unsuitable` / `welcome_skill` / `cargo_type` / `forklift_type` / `equipment_used` / `hard_easy` |
| `work_environment`（No.24） | `temperature` / `safety_gear` / `facilities` / `tenure` / `site_scale` / `locker` / `uniform` / `team_size` |
| `welfare`（No.97） | `facilities` / `parking` / `locker` / `uniform` / `safety_gear` / `commute_allowance` / `social_insurance` |
| `salary_example`（No.64） | `monthly_income_actual` |
| `selection_flow`（No.155） | `start_date` / `web_interview` |
| `probationary_period_supplement`（No.153） | `trial_period` / `training_period` |

**`subtitle`（No.33 キャッチコピー）に専用の質問はない。**キャッチは新しい事実を必要とせず、
他欄で確定した事実から作る。ここが薄いのは事実不足ではなく書き方の問題なので、質問で解決しない。

**`description`は最も多くの質問がぶら下がる欄であり、最も字数が足りない欄でもある。**
仕事内容が400字に届かないときは、`daily_flow`（1日の流れ）を最優先で聞く。
1問で工程・順序・休憩・繁閑をまとめて拾えるため、字数あたりの回収効率が最も高い。

**必須か歓迎かは必ず確認する。**ここを外すと原稿全体（職種名・求める人材・タグ）が総崩れになる。
ただし前回回答があるなら差分確認の形にする（白紙で聞き直さない）。

**年齢構成も必ず確認する。**20〜30代を集めるという依頼の目的に直結し、回答があれば職場情報タグとして
使えるため（扱いは後述）。ただし応募資格には反映しない。

どちらも層3なので、`read` の`■ 層3の差分確認`に出ていればその文をそのまま使う。
出ていない（＝前回回答が無い）ときだけ白紙で聞く。

## 未回答だったときの処理

| 未回答の項目 | 処理 |
|---|---|
| 年齢構成 | 年齢に関するタグ・表現をすべて削除する。既存原稿に付いていても外す |
| 作業量・本数 | 数字を書かない。「◯往復」「1日◯件」を推測しない |
| 資格の必須／歓迎 | **厳しい側に倒す**（必須として書く）。歓迎と書いて実際は必須だと応募者に不利益が出る |
| 残業の有無 | 収入訴求から残業前提の金額を外す |
| 服装・髪型 | 既存タグを維持し、新しい訴求に使わない |
| 1日の流れ | 工程を書かない。「まず◯◯、次に◯◯」を組み立てない |
| 扱う荷物 | 「荷物」のまま書く。品目・重さ・サイズを補わない |
| フォークリフトの機種 | 機種を書かない。資格要件も既存の記載から動かさない |
| 教育期間・1人立ち | 「丁寧に教えます」を書かない（期間の裏付けがないため） |
| 空調・温度環境 | 「快適な職場」「空調完備」を書かない |
| 実際の月収 | 給与例を出さない。時給×時間の計算例も出さない（実態と乖離しうる） |
| 続かない方の傾向 | 求める人材を必須条件だけで止める。適性の記述を作らない |

**未回答が多く、目標字数に届かないまま出す場合。**
チャット本文で「今回この欄が薄いのは、◯◯が未回答のためです」と述べ、
**原稿本文には書かない**（`SKILL.md`「各欄に書くのは、そのまま媒体に載る文字列だけ」）。
テンプレの「未確認のため書かなかった表現」「書かなかった事実欄と、その理由」に落とす。

処理した内容は、出稿用ドキュメントの見出しに必ず明記する（`entry-doc-rules.md` を参照）。
「聞いたが答えが返らなかった」と「そもそも聞いていない」を、後から見て区別できるようにする。

## 既存原稿の矛盾チェック（ヒアリングと同時に投げる）

原稿を書き換える前に、元原稿の中で食い違っている組み合わせを検出する。
**矛盾はスキルが勝手に解消しない。**片方を落とす／両方残すの判断は人間が行う。
ただし、どちらを落としても法令・規約に触れない場合に限り、
「厳しい側・具体的な側を残す」を既定として案に反映し、その旨を見出しに書く。

| 検出する組み合わせ | 既定の扱い |
|---|---|
| タグ`残業なし` ↔ 本文「残業で月◯万円可」「残業して稼ぎたい方歓迎」 | 収入訴求から残業分を外す。要確認として報告 |
| タグ`服装自由` ↔ タグ`制服あり` | `制服あり`を残す（具体的な側） |
| タグ`要経験` ↔ タグ`ブランクOK` | 応募資格の回答に従う。未回答なら`要経験`を残す |
| タグ`未経験歓迎` ↔ 本文「必須資格」 | 資格が必須なら`未経験歓迎`を外す |
| タグ`主婦・主夫歓迎` ↔ フルタイム固定シフト | 勤務時間が固定なら外す |
| 年齢タグ ↔ 年齢構成が未回答 | 全削除（根拠がない） |

## 年齢・性別・国籍の扱い（3つに分ける）

法令が禁じているのは**応募条件としての制限**であって、職場の状況を事実として書くことではない。
この2つを混ぜない。混ぜると、20〜30代に届けるという依頼の目的そのものを削ることになる。

### ① 応募資格・応募条件として書く → 禁止（例外なし）

- 「20〜35歳の方」「若い方歓迎」「男性歓迎」を**応募資格欄・条件欄に書かない**。
  労働施策総合推進法9条（募集・採用における年齢制限の禁止）、男女雇用機会均等法5条。
- ヒアリングで年齢構成の回答が得られても、**応募資格には反映しない**。ここは動かせない。

### ② 職場情報として書く → 裏取りできれば可

- 求人媒体は職場情報のタグとして年齢構成を用意している。**フロントから回答が返った場合に限り**使う。
- 回答が`不明`／未回答なら**全削除**する。既存原稿に付いていても外す（根拠がないため）。
- 「女性活躍中」「男女ともに歓迎」は、両方が併記されていて情報量がゼロのため使わない。
  性別の明示ではなく、実際の職場条件（更衣室の有無・力仕事の有無）を書く。

### ③ 本文の訴求

20〜30代に届く主役は属性の明示ではなく、**その年代が実際に気にする条件**である
（帰宅時間が読める／手作業の負担がない／土日が固定で休める／収入の振れ幅が小さい）。
年齢タグは補助であって主役ではない。タグだけ足して本文が変わっていない案は作らない。

内容確認書の行35（年齢・性別・国籍・資格）は読み込み対象に含めない。

## 出力（チャットに出す形）

質問は次の形で1回だけ出す。**この時点では3案を出さない。**

```
出稿前に◯点確認させてください。分からないものは「不明」で構いません。
すべて埋まらなくても原稿はお出しします。

【原稿の内容に直結するもの】
1. （1日の流れ）始業から終業までを、ざっくり教えてください（朝礼→◯◯→休憩→◯◯）。
2. （扱う荷物）何を運びますか。重さ・大きさの目安も教えてください。
3. （作業の内訳）フォーク◯割・検品◯割など、割合はどれくらいですか。
4. （教育）入って何日くらい先輩が付きますか。1人でできるまでの目安は。
5. （人数）同じ業務に何名くらいで入っていますか。

【応募条件に関わるもの】
6. （応募資格）◯◯免許は必須ですか、歓迎ですか。
7. （年齢構成）いま現場で働いている方は、どの年代が多いですか。

【職場環境・待遇】
8. （空調）屋内の空調はありますか。夏・冬の温度環境は。
9. （設備）食堂・休憩室・ロッカーはありますか。
10. （月収）実際に働いている方の月収は、いくらくらいですか。

※お答えいただけなかった項目は原稿に書きません（推測では埋めません）。
※ご回答をいただいてから、A〜E の5案をお出しします。
```

問数は上の例に固定ではない。**埋まっていない欄から引いた結果の数**である。
すでに`確認済み`の事業所なら1〜2問で終わることもあるし、初回なら15問を超えることもある。
見出し（【原稿の内容に直結するもの】など）で束ねると、フロントが答える順序を選べる。
