# 出稿用ドキュメントの規約

事務員がこのドキュメントだけを見て AirWork にコピペ入稿できる状態を作る。
読み手は求人原稿を書いた人ではない。**判断させない。コピペ元だけを渡す。**

## 構成

| 要素 | 内容 |
|---|---|
| ファイル名 | `記載項目_{派遣先名}`。**案件番号・案の記号・日付を入れない**（`make_entry_doc.py` が弾く）。案件番号はタブ名の役目 |
| タブ名 | 既存求人は**案件番号**（例 `12204054`）。新規案件は`YYYYMMDD_派遣先名`（例 `20260802_◯◯運送`）で作り、AirWorkで採番されたあとに案件番号へリネームする。1案件1タブ。同じ派遣先の別案件はタブを足す |
| 本体 | 176行×4列の表（No. / 項目名 / 内部キー / **事務員転記**）**だけ** |

## 1派遣先 = 1ドキュメント（ファイルを増やさない）

**同じ派遣先のドキュメントは1本しか作らない。案件はタブで増える。**

`make_entry_doc.py` は保存先フォルダを `--title` の名前で検索し、次のように振る舞う。

| 状況 | 動き |
|---|---|
| 同名ドキュメントが無い | 新規作成 → フォルダへ移動 → ルートタブを `--tab` にリネーム |
| ある・`--tab` のタブが無い | **そのドキュメントにタブを足す**（`addDocumentTab`） |
| ある・`--tab` のタブもある | **そのタブの中身を消して書き直す**（作り直し。タブは増えない） |
| 同名ドキュメントが2本以上 | **停止する**。どちらが正か決まらないまま書き足さない |

同じ案件を何度作り直してもファイルもタブも増えない。
「記載項目_◯◯」が何本もできて、どれが正か分からなくなる状態を機械が作らない。

同名が2本になるのは人が手でコピーしたときだけなので、そのときは止めて人に選ばせる。
片方を `bk` へ退避してから実行し直す。

## 見出しも注記も入れない

**中身は表だけにする。**ドキュメント名・項目数・凡例・ヒアリング結果・未回答項目・
書かなかった表現・書き換えた項目のNo. —— どれも入れない。

これは事務員にそのまま渡す作業指示であって、報告書ではない。
事務員は「事務員転記」列を上から順に処理するだけでよく、経緯は手を動かすのに要らない。
上に説明文があると、まずそれを読ませることになる。

経緯の残し先は次のとおり。

| 情報 | 残し先 |
|---|---|
| ヒアリング結果・未回答項目 | ヒアリング履歴スプレッドシート（`scripts/hearing_log.py append`） |
| 未確認のため書かなかった表現・書き換えた項目 | フロント／FooT様へのチャット報告 |

事務員転記の列には、貼る値そのものか日本語の指示（`【削除】…` / `【要確認】…` / `（入力なし）`）が入るので、
凡例が無くてもセルを読めば手が動く。色分けはその補助であって、色の説明は要らない。

## 「事務員転記」列の状態（空セルを残さない）

事務員は原稿を書いた人ではない。空セルを見せると「入れないのか／消すのか／書き忘れなのか」を
**事務員に判断させることになる**。だから空のまま出さず、必ず次のどれかにする。

| 状態 | セルの中身 | 事務員の作業 | 背景色 |
|---|---|---|---|
| 貼る | 値そのもの | AirWork の同じ項目にそのまま貼る | なし |
| 消す | `【削除】今の「◯◯」を消して空欄にする` | いま入っている値を消す | 薄い黄色 `rgb(1,.95,.80)` |
| 判断待ち | `【要確認】今の「◯◯」は裏が取れていません。残すか消すかを決めてください` | **手を止めてフロントに聞く** | 薄いピンク `rgb(1,.89,.89)` |
| 触らない | `（入力なし）` | 何もしない（もとから空） | ライトグレー |
| 触らない | `（社内管理用。触らない）` | 何もしない（求人メモ。単価が入るので値を出さない） | ライトグレー |

`【削除】` には**何を消すのか**まで書く。「タグを整理してください」では事務員が現物を探しに行く。

`【要確認】` を貼る・消すと同じ見た目にしない。同じに見えると事務員がその場で自分で決めてしまう。
このスキルは**事務員に判断させないこと**を前提に作っているので、色で明確に外す。
なお `【要確認】` は入稿指示ログにも載せない。まだ指示が確定していないものを載せると、
永久に「未反映」と数えられ続ける。

### 「（変更なし）」は使わない（2026-08-02 変更）

**書き換えていない項目にも、いま掲載されている値をそのまま書く。**
以前は `（変更なし）` と書いていたが、それだと事務員は AirWork の画面を開いて
「今なんと入っているか」を自分で確かめることになる。それは転記ではなく確認作業であり、
「コピペで出稿できる状態」になっていない。

ドキュメントは長くなるが、**上から順に貼れば終わる**ことを優先する。

これらの状態は `apply_plan.py --current` が付ける。`--current` は Joblist の現在値
（内部キー→値）を渡すもので、**これが無いと書き換えていない項目まで `（入力なし）` になり、
事務員が今の掲載内容を消してしまう**。既存求人の修正では必須。
新規入稿は現在値が存在しないので `--current` を省く。

### 「書けなかった」と「消したい」を同じ値で表さない（2026-08-03 変更）

`--plan` の値は4種類ある。

| 値 | 意味 | 事務員転記の列に出るもの |
|---|---|---|
| 文字列 | この値を貼る | 値そのもの |
| `""` | 情報が足りなくて書けなかった | **現在値をそのまま残す**（消さない） |
| `"__DELETE__"` | 消すと決めた | `【削除】今の「◯◯」を消して空欄にする` |
| `"__REVIEW__"` | 裏が取れないので人に決めさせる | `【要確認】…残すか消すかを決めてください` |

以前は `""` を削除として扱っていた。甲山機工のテストでヒアリング20問中17問が「不明」で返り、
書けなかった4欄が全部 `【削除】` になった。掲載中の「土日休み・連休あり・身体の負担少なめ」
「月収50万円以上可」「給与上限3000円」が消える指示になり、**求人が痩せた。**
情報が足りないときに既存の掲載内容を消すのは、リライトではなく破壊である。
書けないなら手を触れない。消すなら消すと明示させる。

契約で決まっている項目（雇用形態・勤務地・給与形態・試用/研修期間の条件）は
`--plan` に入れると `apply_plan.py` が停止する。原稿づくりで動かしてよい値ではない。

## チャット報告に必ず入れる5点

ドキュメントではなく**チャットで**フロント・FooT様へ伝える。
後から「なぜこう書いたのか」を追えるようにするための情報で、事務員の作業には要らない。

```
■ヒアリング結果：勤務地＝◯◯／◯◯免許＝必須／年齢構成＝未回答／◯◯＝未回答
■未回答だった項目は原稿に使っていません（推測で埋めていません）。
■未確認のため書かなかった表現：「◯◯」「◯◯」
■年齢タグ：未回答のため全削除／◯代が多い（ヒアリングで確認）
■今回書き換えた項目：No.3 職種名／No.7 仕事内容／No.23 職場環境／No.28 求める人材／No.33 キャッチコピー／No.63 給与の補足説明
```

「未回答」と「未確認のため書かなかった表現」を分けて書く。
前者は聞いたが答えが返らなかった項目、後者はそもそも根拠がないので使わなかった表現である。

年齢タグは**回答が返った場合のみ職場情報として書く**。未回答なら既存タグも含めて全削除し、
その事実をチャット報告に残す。**応募資格欄には年齢を一切書かない**（`hearing-protocol.md` を参照）。

由来が `前回推測` の表現をそのまま流用しない。使うなら今回のヒアリングで裏を取り、
`確認済み` に変えてから書く（判断基準は `SKILL.md` 手順3の由来ラベル表）。

## 表の書式

| 項目 | 値 | 理由 |
|---|---|---|
| 余白 | 上下左右 36pt | A4使用可能幅 523.3pt を確保する |
| 列幅 | `[30, 105, 138, 248]` = 521pt | 523.3pt 未満。超えると表が用紙からはみ出す |
| フォントサイズ | 9pt | 176行を現実的な枚数に収める |
| ヘッダ行 | グレー `rgb(.82,.84,.87)` | |
| `（入力なし）`『（社内管理用。触らない）』の行 | ライトグレー `rgb(.96,.96,.96)` | **触らなくてよい行が一目で分かる** |
| `【削除】` の行 | 薄い黄色 `rgb(1,.95,.80)` | **貼る作業と消す作業を見た目で分ける** |
| `【要確認】` の行 | 薄いピンク `rgb(1,.89,.89)` | **事務員の手をここで止める（判断させない）** |

色は「値の有無」ではなく「事務員が何をするか」で分ける。値の有無で塗ると、
貼る・消す・触らないが同じ見た目になり、結局1行ずつ読ませることになる。

空欄扱いにする文字列は `"" / — / - / ― / ー / －`。AirWork の CSV はこれらを空欄に使う。
これらが `事務員転記` 列に残ったまま `make_entry_doc.py` を実行すると**異常終了する**
（空欄のまま事務員に渡さないための門）。

## No. の採番体系（取り違え注意）

| 版 | タブ | 用途 |
|---|---|---|
| **176項目版** | 出稿用ドキュメント | AirWork の入力・選択可能項目。**このドキュメントのNo.はこちら** |
| 265項目版 | Joblist スプレッドシート | エクスポートCSVの列。集計・lint用 |

**両者のNo.は一致しない。**No.で会話するときは必ずどちらかを明示する。

## 生成手順

```bash
# 0) 現在の掲載値を取り出す（内部キー→値のJSON）。既存求人の修正では必須
python3 scripts/fetch_current.py --client foot --job 12204054 --output /tmp/current.json

# 1) 選ばれた案を176項目に適用し、空セルを埋める
#    （書き換えていない項目には --current の現在値がそのまま入る）
python3 scripts/apply_plan.py \
    --items references/clients/foot/items176-master.json \
    --plan  /tmp/plan_selected.json \
    --current /tmp/current.json \
    --output /tmp/items176_selected.json

# 2) ドキュメント作成（表と値だけ。見出し・注記は入れない）
#    先に転記前チェック（precheck_doc.py）が内部で走る。NGが1件でもあれば作られない
#    末尾で入稿指示ログへ自動追記される（別コマンドは不要）
python3 scripts/make_entry_doc.py \
    --items /tmp/items176_selected.json \
    --title 記載項目_派遣先名 \
    --tab   12204054 \
    --client foot \
    --state /tmp/doc_state.json \
    --current /tmp/current.json \
    --request /tmp/request.json \
    --siblings /tmp/siblings.json

# 3) 書式適用
python3 scripts/style_entry_doc.py \
    --items /tmp/items176_selected.json \
    --state /tmp/doc_state.json
```

`--plan` は `{"3": "職種名", "7": "仕事内容", ...}` 形式。値の意味は前節の4種類。

## 転記前チェック（precheck_doc.py）

**`make_entry_doc.py` が内部で必ず呼ぶ。飛ばすオプションは無い。**
チェックを外せるようにすると、急いでいるときほど外される。そして外したことは誰も覚えていない。
実際 2026-08-03 の甲山機工では、掲載中の「土日休み・連休あり」と月収例が消える指示のまま
ドキュメントが出来上がり、人が目で気づくまで誰も止めなかった。

| ID | 見るもの | 深刻度 |
|---|---|---|
| P1 | 掲載中より情報が減っていないか（削除指示・7割未満への短縮） | NG |
| P2 | 契約で決まっている項目が書き換わっていないか | NG |
| P3 | 依頼の採用予定人数・時給・勤務時間が反映されているか | NG |
| P4 | 依頼と掲載中が食い違っていないか（確認が済んでいるか） | NG |
| P5 | 職種名に金額・時刻が混ざっていないか | NG |
| P6 | 職種名・キャッチ・仕事内容・求める人材＋表示欄に年代／性別／国籍が出ていないか | NG |
| P7 | 空セルが残っていないか | NG |
| P8 | 15欄の合計が目標の6割に届いているか | WARN |
| P9 | 同じ言い回しが3欄以上に出ていないか（条件の反復で字数を埋めていないか） | WARN |
| P10 | 説明口調（`references/writing-style.md`）・60字超の文の連発 | WARN |
| P11 | 兄弟求人に素材があるのに使い残していないか | WARN |
| P12 | 情報不足で書けなかった欄に現在値を残したこと | WARN |

P6 は「不問」と書けば安全、ではない。`年齢不問` `性別不問` `国籍不問` は違法ではないが、
書いた時点で読者にその軸を意識させる。年代は No.23 の職場情報タグへ逃がす設計なので、
本文に年齢・性別の語が出る理由がそもそも無い。語ごと拾う。
`日本籍の方を歓迎` `永住者の方歓迎` のように「国籍」の語を含まない言い換えも同じ扱いにする
（言い換えを並べていないと素通りする）。

`--current` / `--request` / `--siblings` を渡すほど厳しくなる。渡さないと比べる相手がいないので
その項目は自動で外れる（新規案件では P1・P2・P4 が外れる）。

例外を通すときは明示する。意図して掲載情報を減らすなら `--allow-shrink 24,64`、
依頼と掲載中の食い違いをフロントに確認済みなら `--confirmed hours,wage`。
**黙って通る道は用意していない。**

`--request` は依頼フォーマット7項目をそのまま JSON にしたもの。

```json
{"site":"派遣先名","office":"事業所名","title":"職種","duty":"任せる仕事",
 "hours":"8:00-17:00","wage":"2000円","hires":"1名"}
```

`apply_plan.py` は `--output` の隣に `<output>.meta.json` も書く。書き換えたNo.だけの小さなファイルで、
出来上がった176項目JSONを見ても「元から入っていた値」と「今回変えた値」は区別できないため、ここで分けている。
次の `make_entry_doc.py` がこれを拾って入稿指示ログへ記録する。**消さない。**

## 入稿指示ログ（出した指示の自動記録）

出した指示は Joblist スプシの**別タブ**（既定 `入稿指示ログ`）へ自動で残る。**手で叩くコマンドは無い。**

| いつ | 何が起きるか | 呼び出し元 |
|---|---|---|
| `make_entry_doc.py` の末尾 | 書き換えた項目を追記（状態=**未確認**） | `log_changes()` → `push_to_joblist.do_append()` |
| 次の `fetch_current.py` の冒頭 | 現在値と突き合わせ **確認済み**／**差分あり** に更新 | `verify_pending()` → `push_to_joblist.do_verify()` |

**`Sheet1` には絶対に書かない。** Joblist の `Sheet1` は AirWork の CSV をまるごと貼り替える運用で、
そこに列を足すと次の貼り替えで消える。`check_sheet_name()` が `Sheet1` / `シート1` 系の名前を
起動時に拒む（大文字小文字は問わない）。書き込み先は `config.json` の
`spreadsheet.logSheetName`。タブが無ければ自動で作る。

列は10列。`記録日時 / 案件番号 / 派遣先 / No. / 項目名 / 内部キー / 指示した値 / 状態 / 照合日時 / AirWorkの実値`

- **記録は必ず「未確認」から始める。**スキルが書けるのは意図までで、事務員が実際に貼ったかは分からない。
  貼った前提で書くと、次に `fetch_current.py` がそれを現在値として読み、
  `【削除】今の◯◯を消して` が存在しない値を消せという指示になる。事務員が一番混乱する壊れ方である。
- **Joblist が「現実」、このログが「意図」。混ぜない。**意図に裏が取れるのは
  AirWork のエクスポートを貼り直したときだけである。
- **確認済みの行は再判定しない。**一度 AirWork に載ったことが取れれば、その指示の役目は終わり。
  一方 **差分ありは次の照合で拾い直す**。ここを対象から外すと、事務員があとから貼っても
  永遠に差分ありのまま残る。
- **同じ (案件番号, 内部キー) は行を増やさず上書きする。**事務員向けの指示は最新の1件しか意味を持たない。
  経緯は出稿用ドキュメントのタブ側に残る。
- 求人メモや `（入力なし）` など**貼る値ではない文字列は照合しない**（`MARKERS`）。
- **`【要確認】` の行は記録も照合もしない。**まだ指示が確定していないものを載せると、
  「1件未反映」と永久に数えられ続ける。人が残すか消すかを決めてから、次の実行で載る。
- **新規案件（`YYYYMMDD_派遣先名` タブ）は記録しない。**AirWork 未採番で照合の相手がいないため、
  記録しても永遠に未確認で残る。`make_entry_doc.py` が採番後に叩くコマンドを表示する。
- **ログの失敗で本体を落とさない。**記録・照合が失敗しても警告だけ出し、ドキュメント生成は成功で終える。
  ここで落とすと、出来上がっているドキュメントを人が「失敗した」と受け取って作り直す。
- `push_to_joblist.py` だけスコープが `spreadsheets`（書き込み可）。`fetch_current.py` は readonly のまま。

## 出してはいけない値

**求人メモ（`job_offer_memo`）の中身を出稿用ドキュメントに載せない。**
`◯◯運送2000/1500` の `2000/1500` は請求単価と支払単価であり、派遣先にも事務員にも見せない。
`fetch_current.py` が伏せ字にし、`make_entry_doc.py` の `check_no_leak()` が最後にもう一度止める。
この項目の事務員転記は `（社内管理用。触らない）` になる。
**現在値をそのまま書く方針の例外はここだけ。**

## 実行上の注意

- 保存先は `--client` から `config.json` の `drive.outputFolderId` を引く。
  33桁のフォルダIDを毎回手で渡さない（貼り間違えると別のフォルダに出る）。
  一時的に別のフォルダへ出したいときだけ `--folder <ID>` で上書きする。
  フォルダIDは `init_client.py` が初期設定で登録し、そのとき書き込めるかまで確認している。
- ファイル名は `check_title()` が検査する。案件番号・「案」・日付が入っていると**起動時に落ちる**。
- 事務員転記が空の行が1つでもあると**起動時に落ちる**。`apply_plan.py --current` を先に通す。
- 転記前チェックが NG を出すと**ドキュメントは作られない**。直してから実行し直す。
  中途半端なドキュメントが残らないよう、API を1回も叩く前に止まる。
- **タブ操作のリクエスト名は discovery document に載っていない。**下の3つは実測で動く。
  一覧に無いからといって「できない」と判断しない（`createTab` / `addTab` / `insertTab` /
  `createDocumentTab` / `deleteDocumentTab` はいずれも存在しない）。

  | 用途 | リクエスト名 |
  |---|---|
  | タブを足す | `addDocumentTab`（`tabProperties.title` / 任意で `index` `iconEmoji`） |
  | タブ名を変える | `updateDocumentTabProperties`（`tabProperties.tabId` + `fields`） |
  | タブを消す | `deleteTab`（`tabId`） |

- 同名タブを探すときは**子タブまで辿る**（`iter_tabs()`）。トップレベルだけ見ると、
  人が入れ子にしたタブを見落として同じ案件のタブを二重に作る。
- Docs API v1 のタブ指定は2系統あり、混ぜると静かに別タブへ書かれる。
  `updateDocumentStyle` はリクエスト直下に `tabId`、`updateTextStyle` は `range` の中に `tabId`、
  `tableStartLocation` は Location なので `index` と同じ辞書に `tabId` を置く。
- セルへの `insertText` は **startIndex の降順**で流す。昇順だと後続のインデックスがずれる。
- batchUpdate は insertText 300件・style 200件ずつに分割する。
- 認証は ADC（`google.auth.default`）。スコープは documents と drive。
